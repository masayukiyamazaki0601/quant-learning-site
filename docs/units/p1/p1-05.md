## 1. リターンの統計：増え方を「割合」で測る

### 1-1 リターン＝「いくら増えたか」ではなく「何%増えたか」

100円が110円になったら、増えたのは10円。でも、1000万円が1010万円になったら、増えたのは10万円。どちらが「大きく増えた」でしょうか？

金額だけで比べると10万円のほうが大きく見えますが、**割合で見るとどちらも+1%で同じ**です。投資の世界では、金額の大小に関係なく比べられるよう、**リターン（収益率）＝「増えた割合（%）」**で測るのが基本です。

??? example "大人の式（クリックで表示。開かなくてOK）"
    前の値段を \(P_{t-1}\)、今の値段を \(P_t\) とすると、
    \[
    \text{リターン} = \frac{P_t - P_{t-1}}{P_{t-1}}
    \]
    意味は「（今 − 前）÷ 前」。100円→110円なら (110−100)÷100 = **+10%** です。

### 1-2 落とし穴：「+10%と-10%で、結局0%」は間違い

ここからが今回の1番のポイントです。

100円の株が、**1日目に+10%（→110円）、2日目に-10%（→99円）**になったとします。

- 「+10% − 10% = **0%**」…… これが**直感的な間違い**
- 実際は 110 × 0.9 = **99円**。つまり **-1%**

なぜか？ 2日目の「-10%」は「最初の100円」ではなく「110円」に掛かるからです（第2週の複利と同じ「掛け算の世界」）。**「+10%と-10%」を足し算で処理してはいけない**——ここが投資の基本中の基本です。

### 1-4 そこで登場するのが「ログリターン」

「掛け算の積み上げを、うっかり足し算してしまう」問題。これを解決するのが **ログリターン** です。

**言葉で言うと**：「+10%」を「×1.1」、「-10%」を「×0.9」と考えると、2日間のトータルは「×1.1×0.9」という**掛け算**。ログリターンは、この「掛け算を、足し算に変換するメガネ」です。変換すると「+10% → +0.0953」「-10% → -0.1054」という数字になり、**足し算すると -0.0101 ≈ -1.0%**——実際の答えとぴったり一致します。

??? example "大人の式（クリックで表示。開かなくてOK）"
    ログリターンは、\( \ln(\frac{P_t}{P_{t-1}}) \) で計算します（\(\ln\) は「対数」という変換。中学では扱わないので、今は「変化率を足し算できる形に変換する道具」でOK）。

    変換すると「掛け算の積み上げ」が「足し算の積み上げ」になる。だから長い期間のリターンを扱う金融の現場では、この「ログ」を使うのが普通です。

### 1-5 Pythonで確かめる：Pandasでリターンを計算する

```python
import numpy as np
import pandas as pd

price = pd.Series([100, 110, 99], index=["1日目", "2日目", "3日目"])

ret = price.pct_change()        # 単利リターン（前日との差の割合）
log_ret = np.log(price).diff()  # ログリターン

print("価格:")
print(price)
print("\n単利リターン:")
print(ret.round(4))
print("\nログリターン:")
print(log_ret.round(4))
```

```text
価格:
1日目    100
2日目    110
3日目     99

単利リターン:
1日目    NaN
2日目    0.1
3日目   -0.1

ログリターン:
1日目       NaN
2日目    0.0953
3日目   -0.1054
```

そして「2日間のトータル」を3つの方法で比べると：

```python
print("単利を足す   =", round(float(ret.sum()), 4))
print("実際(掛け算) =", round(110/100 * 99/110 - 1, 4))
print("ログを足す   =", round(float(log_ret.sum()), 4))
```

```text
単利を足す   = 0.0
実際(掛け算) = -0.01
ログを足す   = -0.0101
```

- 単利リターンを足すと **0%**（＝間違い）
- 実際のトータルは **-1%**
- ログリターンを足すと **-1.01%**（≈実際の答えと一致）

これが「金融のデータ分析では、価格の代わりにログリターンをよく使う」理由です。**Pandasで `pct_change()` と `np.log(price).diff()` の2つを覚えれば、日々の株価データを分析する準備ができた**、ということになります。

## 2. 行列の「分解」：対角化・SVDの予告

### 2-1 分解＝複雑なものを「部品」に分ける

お絵かきアプリで、1枚の複雑なイラストを編集するときのことを思い浮かべてください。「背景」「キャラクター」「文字」のように**レイヤー（層）に分けておくと**、背景だけ消したり、キャラだけ動かしたりできますよね。

行列の「分解」も、これと同じです。**大きな行列（数字の表）を、意味のある部品の組み合わせに分ける**こと。

- 対角化 … 特別な行列を「計算しやすい形（対角行列）」に分解する方法
- **SVD** … どんな行列でも分解できる、もっと万能な方法

名前は難しいですが、**やっていることは「絵をレイヤーに分ける」と同じ**です。

### 2-2 SVDのすごいところ：「大事な部品から順に」取り出せる

SVDの特徴は、分解した部品に「重要度の順番」が付くことです。

- 全部の部品を重ねると、元の表にぴったり戻る
- でも**大事な部品だけで重ねても、「だいたい同じ」になる**

つまり、**細かい部品を捨てても、ほとんど同じ情報が残る**。これはデータの世界で大活躍します。

- **顔写真の圧縮**：画素の行列をSVDで分解 → 大事な成分だけ残すと、画質はほとんど同じままファイルが小さくなる
- **おすすめ（レコメンド）**：「ユーザー×商品」の大きな表を分解すると、「こういう人にはこういう商品」という**好みのパターン**が取り出せる
- **主成分分析（PCA）**：たくさんの項目があるデータを、SVDで「大事な方向」に要約する（フェーズ3で詳しくやります）

今は「**行列を分解すると、データの大事な部分が見えてくる**」というイメージだけ持っておいてください。使うための計算は、フェーズ3でPythonに任せて覚えます。

### 2-3 なぜ今、この話をするの？

第4週で「数字の表＝行列」を学び、今回「リターンを表で計算（Pandas）」を始めました。ここから先のデータ分析は、ずっと「表の計算」です。その先に「表を分解して要約する」SVDが待っている——という**地図の一枚目**として、名前とイメージを今のうちに覚えておくと、フェーズ3で「あれか！」となります。
