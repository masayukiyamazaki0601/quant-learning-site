## 1. 確率と条件付き確率：「〜のとき」で確率は変わる

### 1-1 確率の基本（中学の復習）

サイコロを1回振って「偶数の目（2・4・6）が出る確率」は？

- うまくいく場合：3通り
- 全部の場合：6通り
- 確率 = 3 ÷ 6 = **50%**

これが確率の基本です。**「うまくいく場合 ÷ 全部の場合」**。分数のままでも、％にしてもOKです。

### 1-2 条件付き確率：「雨の日」に限ると、遅刻確率は上がる？

ある1年間（365日）の記録がこうだったとします。

| | 日数 | うち遅刻した日 |
| --- | --- | --- |
| 1年全体 | 365日 | 15日 |
| うち「雨の日」 | 60日 | 6日 |

- **1年全体で見た遅刻確率**：15 ÷ 365 ≈ **4.1%**
- **「雨の日」に限った遅刻確率**：6 ÷ 60 = **10%**

「雨の日」という**条件を付けると**、確率は4%から10%に上がります。このように「○○のとき」と条件を限定した確率を、**条件付き確率**と呼びます。

日常で言えば「降水確率80%だから傘を持っていく」も、これと同じ考え方です。天気予報は「明日、雨が降る確率」を教えてくれる——つまり**条件（明日）付きの確率**を日々使っています。

??? example "大人の式（クリックで表示。開かなくてOK）"
    条件BのときAが起きる確率を \(P(A \mid B)\) と書きます（\(\mid\) は「〜という条件で」の意味）。
    \[
    P(A \mid B) = \frac{A\text{ と }B\text{ が両方起きる場合の数}}{B\text{ が起きる場合の数}}
    \]
    雨と遅刻の例なら「(雨の日の遅刻6日) ÷ (雨の日60日) = 10%」です。

### 1-3 Pythonで確かめる

```python
total_days = 365
rain_days = 60
late_on_rain = 6
late_all = 15

print(f"1年全体の遅刻確率: {late_all / total_days * 100:.1f}%")
print(f"雨の日の遅刻確率: {late_on_rain / rain_days * 100:.1f}%")
```

```text
1年全体の遅刻確率: 4.1%
雨の日の遅刻確率: 10.0%
```

「条件を付けると確率が変わる」——この当たり前だけど大事な感覚が、次章の「ベイズ」の土台になります。

## 2. ベイズの考え方：検査で「陽性」でも、本当に病気とは限らない

### 2-1 問題設定：まれな病気の検査を1000人にやった

次のような**まれな病気の検査**を考えます。

- 1000人に1人ではなく、分かりやすく **1000人中10人（1%）** がこの病気
- 検査の精度はとても良い：**本当に病気の人をほぼ全員「陽性」**と出せる（10人中10人）
- でも、**健康な人でも2%は「陽性」**と出てしまう（これを「偽陽性（ぎようせい）」と呼びます）

1000人の内訳を表にするとこうなります。

| （1000人） | 実際は病気 | 実際は健康 | 計 |
| --- | --- | --- | --- |
| **検査が陽性** | 約10人 | 約20人 | **約30人** |
| 検査が陰性 | 約0人 | 約970人 | 約970人 |
| 計 | 10人 | 990人 | 1000人 |

※健康な人990人の2% ≈ 20人が「健康なのに陽性」。これが偽陽性です。

### 2-2 大事な質問：「陽性でした」と言われた人の中に、本当に病気の人は何人？

ここがベイズの考え方の核心です。検査で「陽性」と出る人は、表の上から1行目＝**約30人**います。

その30人のうち、本当に病気なのは**約10人**。

だから、

\[
\frac{10}{30} \approx \mathbf{33\%}
\]

**「陽性」と言われても、本当に病気の確率は約33%。**「検査が当たる」と「陽性の人が本当に病気」は、全然ちがう話なんです。

### 2-4 なぜこうなるの？「もともと病気の人が少ない」から

検査の精度は99%と高いのに、なぜ陽性でも33%しか当たらないのか。理由はシンプルです。

**もともと病気の人が少ない（1%）から、健康な人（99%）のうちの「ちょっとした誤り（2%）」が、陽性の大半を占めてしまう。**

- 病気の人10人 → ほぼ全員 陽性（10人）
- 健康な人990人 → その2% = 約20人が 偽陽性

10人 vs 20人。**偽陽性のほうが多い**から、陽性でも「本当に病気」は3人に1人になるわけです。

この「結果（陽性）を見たあとの確率」を、**「もともとの確率（病気の人は1%）」と「検査の精度」の両方から計算し直す**方法が、**ベイズの定理**です。名前はかっこいいですが、やっていることは上の表を書いて割り算するだけ。式は開かなくてOKの箱に入れておきます。

??? example "大人の式（クリックで表示。開かなくてOK）"
    病気であることを \(D\)、陽性を \(+\) と書くと、
    \[
    P(D \mid +) = \frac{P(+\mid D)\,P(D)}{P(+\mid D)\,P(D) + P(+\mid \text{健康})\,P(\text{健康})}
    \]
    意味は「陽性という結果を、①本当に病気で陽性の人 と ②健康なのに陽性の人（偽陽性）に分けて、①の割合を出す」。さっきの 10 ÷ (10+20) と同じ計算です。

### 2-5 実社会での使われ方（予告）

この考え方は、この先のユニットで何度も出てきます。

- **機械学習のスパム判定**：「『お金』という言葉が入るメール」だけ見ると、大事なメールまでスパム扱いされる（フェーズ3で対策を学びます）
- **感染症の検査**・**ガンの検査**：「まれな病気ほど、陽性でも要注意」の解釈に必須
- **投資のシグナル**：「このサインが出たら上がる」も、そもそも上がる確率が低いと当てにならない

## 3. データ取得：実際の株価を手に入れる

### 3-1 ここまでの例は「手作り」。今度は本物のデータを取ろう

ここまでのUnitでは、分かりやすくするために数字をこちらで用意していました。でも実際の分析では、**自分でデータを取る**必要があります。

Pythonには、株価を取得できるライブラリがいくつかあります。一番手軽なのが **yfinance**（Yahoo!ファイナンスのデータを使うライブラリ）です。

```bash
# 初回だけインストール
.venv/bin/pip install yfinance
```

```python
import yfinance as yf

# トヨタ自動車（7203.T）の2024年の終値を取得
df = yf.download("7203.T", start="2024-01-01", end="2024-12-31")["Close"]

print(df.head())   # 最初の5行
print(df.tail())   # 最後の5行
```

実行すると、**左に日付、右に終値**が並んだ「表」（PandasのDataFrame）が返ってきます。この「表」こそ、第4週で学んだ行列そのもの。取得したデータに、第5週のリターン計算（`pct_change()`）をそのまま適用できます。

!!! note "実行結果について"
    出力される数字は**その日の実際の株価**なので、環境やデータの状況によって変わります（上のコードを動かしたときの結果が正解です）。
    もしYahoo!に繋がらない場合は、銘柄コードや期間を変えて試してみてください。yfinanceは無料ですが、たまにサーバー側の都合で一時的に使えないことがあります。

### 3-2 可視化：折れ線グラフで「見る」

取得したデータは、`plot()` で一発でグラフにできます。

```python
import matplotlib.pyplot as plt

df.plot(figsize=(10, 4), title="トヨタ自動車（7203.T）終値", ylabel="円")
plt.show()
```

これを手元で実行すると、1年間の株価の上がり下がりが1本の線になって見えます。**「数字を表で扱い、グラフで見る」**——これがデータ分析の基本動作で、このサイトの動く図も同じ考え方で作っています。

### 3-3 次の週への橋渡し：取ったデータで「復習」

せっかく本物のデータが手に入ったので、第5週の復習を1つ。終値の列に `pct_change()` を掛けるだけで、日次リターンの列が作れます。

```python
df.pct_change().tail()   # 日次リターン（前日比）
```

- 日次リターンがだいたい何%くらいか
- プラスの日とマイナスの日、どちらが多いか

この「データの平均やばらつきを見る」作業が、第7週以降の**統計学**のスタート地点です。確率（今回）とデータ（今回）がそろったので、次はいよいよ「手元のデータから結論を出す」道具を学びます。
