## 1. 多変数の関数：「入力が2つ」の世界

### 1-1 中学の関数は「入力が1つ」

中学でならった「関数」は、だいたい入力が1つでした。たとえば

- 走った距離 = 速さ × 時間（速さを決めれば、距離は時間だけで決まる）

でも、現実の計算は**入力が2つ以上**のものがほとんどです。たとえば……

### 1-2 バイト代は「時給」と「時間」の2つで決まる

あなたがコンビニでバイトをしているとします。

**バイト代 = 時給 × 働いた時間**

- 時給1200円 × 5時間 = 6000円
- 時給1200円 × 8時間 = 9600円

「時給」と「時間」の2つの入力で、バイト代が決まります。これが「変数が2つある関数」＝ **多変数の関数**です。同じような例は身の回りにいっぱいあります。

| 例 | 2つの入力 |
| --- | --- |
| バイト代 | 時給 × 働いた時間 |
| ラーメン屋の売上 | 客の数 × 1人あたりの注文金額 |
| 壁紙を張る面積 | たての長さ × よこの長さ |
| ガソリン代 | 走った距離 ÷ 燃費 × ガソリン単価 |

### 1-3 大事なのは「1つだけ動かす」

入力が2つあると、「全部いっぺんに考える」のは難しい。そこで使うのが、**ほかの入力はそのままにして、1つだけ動かす**という作戦です。

たとえば「時給1200円」のままで、

- **働く時間を1時間ふやす**と、バイト代はいくら増える？ → **+1200円**
- **時給を100円上げる**と、バイト代はいくら増える？（8時間働くとして）→ **+800円**

お気づきですか？ 「**どれを動かすか**」で、答えが変わります。

- 時間を動かした → 「1時間あたりいくら増えるか」＝ **時給そのもの（1200円）**
- 時給を動かした → 「時給100円につきいくら増えるか」＝ **働いた時間×100（8時間なら800円）**

この「1つの変数だけを動かして、変化の割合を測る」考え方。これこそが、大学の数学で「**偏微分（へんびぶん）**」と呼ばれるものの入り口です。名前は難しいですが、やっていることは **「どっちの方向で測るか」を決めて、微分する**だけです。

> 覚える1行：**偏微分＝「1つの変数だけ動かしたときの、変化の割合」**

### 1-4 なぜ金融で偏微分が大活躍するのか

オプションの価格は、「株価」「残り時間」「金利」……と**たくさんの入力**で決まります（第2週の予告どおり）。

- 「株価を1円動かしたら、オプション価格はいくら動く？」→ 株価で偏微分 → これが **デルタ**
- 「時間が1日たつと、いくら動く？」→ 時間で偏微分 → これが **セータ**

「どの入力で測るか」をはっきりさせないと、話が始まらない。だから偏微分が金融の基本になるわけです（詳しくはフェーズ2で）。

### 1-5 Pythonで確かめる：どっちを動かすかで答えが変わる

```python
def baito(wage, hours):        # バイト代 = 時給 × 時間
    return wage * hours

print("【働く時間を1時間ずつふやしたら（時給1200円のまま）】")
for h in [5, 6, 7, 8]:
    print(f"  {h}時間 → {baito(1200, h)}円（+{baito(1200, h) - baito(1200, h-1)}円）")

print("【時給を100円ずつ上げたら（8時間のまま）】")
for w in [1000, 1100, 1200, 1300]:
    print(f"  時給{w}円 → {baito(w, 8)}円（+{baito(w, 8) - baito(w-100, 8)}円）")
```

```text
【働く時間を1時間ずつふやしたら（時給1200円のまま）】
  5時間 → 6000円（+1200円）
  6時間 → 7200円（+1200円）
  7時間 → 8400円（+1200円）
  8時間 → 9600円（+1200円）
【時給を100円ずつ上げたら（8時間のまま）】
  時給1000円 → 8000円（+800円）
  時給1100円 → 8800円（+800円）
  時給1200円 → 9600円（+800円）
  時給1300円 → 10400円（+800円）
```

時間を1時間動かすと毎回 **+1200円（＝時給）**、時給を100円動かすと毎回 **+800円（＝8時間ぶん）**。「どっちの方向で測るか」で変化の量が違う——これを目で見られる図が次です。

## 2. お金の時間価値：お金には「時間」という値札が付いている

### 2-1 今日の1000円と、1年後の1000円。どっちがうれしい？

おじいちゃんが、こう言ったとします。

> 「今日、お年玉として1000円あげようか。それとも、**1年後**に1000円あげようか」

どっちがうれしいですか？ もちろん**今日**ですよね。理由は簡単で、今日もらえば

- すぐに使える
- 銀行に預ければ、金利ぶん増える（年5%なら、1年後には **1050円**）

つまり「**同じ1000円でも、もらうのが早いほうが価値が高い**」。この「時間によってお金の価値が変わる」性質を、**お金の時間価値**と呼びます。金融の考え方の土台の土台です。

### 2-2 将来のお金を「いまの価値」に直す（＝割引）

では逆を考えます。

> 「1年後に100万円もらえる約束」は、**いまのいくら**と同じ価値？

年利5%の銀行に預ければ、いまの **x円** は1年後に x × 1.05 円になります。だから x × 1.05 = 100万円 となる x を求めればいい。両辺を1.05で割って

\[
x = 100 \div 1.05 \approx 95.2万円
\]

**1年後の100万円は「いまの約95.2万円」と同じ価値**です。このように「将来のお金」を「いまの価値」に直すことを **割引（わりびき）**、直したあとの金額を **現在価値（げんざいかち）** と呼びます。

2年後なら「1.05を2回割る」、10年後なら「1.05を10回割る」だけです。表にするとこうなります（どれも「100万円を将来もらう約束」の現在価値）。

| もらう時期 | 計算 | いまの価値 |
| --- | --- | --- |
| 1年後 | 100 ÷ 1.05 | 約95.2万円 |
| 5年後 | 100 ÷ 1.05⁵ | 約78.4万円 |
| 10年後 | 100 ÷ 1.05¹⁰ | 約61.4万円 |
| 20年後 | 100 ÷ 1.05²⁰ | 約37.7万円 |

**「遠い将来のお金ほど、いまの価値が小さい」**——これが時間の価値のキモです。

??? example "大人の式（クリックで表示。開かなくてOK）"
    年利を \(r\)（5%なら0.05）、受け取るまでを \(t\) 年とすると、将来の金額 \(C\) の現在価値 \(PV\) は

    \[
    PV = \frac{C}{(1+r)^t}
    \]

    意味は「(1+r) を t回かけたもので割る」。分数で書いてあるだけで、やっていることは2-2の割り算と同じです。

### 2-3 Pythonで確かめる：100万円は、何年先になると目減りする？

```python
def genzai_kachi(future, r, t):     # 現在価値 = 将来の金額 ÷ (1+r)^t
    return future / ((1 + r) ** t)

for t in [1, 5, 10, 20]:
    print(f"{t:>2}年後 → いまの価値 ≈ {genzai_kachi(100, 0.05, t):.1f}万円")
```

```text
 1年後 → いまの価値 ≈ 95.2万円
 5年後 → いまの価値 ≈ 78.4万円
10年後 → いまの価値 ≈ 61.4万円
20年後 → いまの価値 ≈ 37.7万円
```

20年後の100万円は、いまの **約37.7万円**。100万円が3分の1ちょっとまで「目減りして見える」感覚をつかんでください。

### 2-5 これが「金利が上がると債券の値段が下がる」理由

第2週で「金利が上がると債券の値段は下がる」と言いました。ここで理由が説明できます。

債券は「将来、利子と元本を払ってもらえる約束」。その**いまの値段**は「もらえるお金をぜんぶ現在価値に直して足したもの」で決まります。

- 金利が **低い**（1%）→ 割る数が小さい → 現在価値が大きい → **債券の値段は高い**
- 金利が **高い**（10%）→ 割る数が大きい → 現在価値が小さい → **債券の値段は安い**

図2の「金利10%（赤い線）」がほかの線よりぐっと下に沈むのを思い浮かべてください。**金利と債券の値段はシーソーの関係**。これが債券投資の基本中の基本です（どのくらい敏感に動くかを数字にするのが、第4週のデュレーションです）。

## 3. 利回り：1年で「何%もうかるか」をはかる物差し

### 3-1 債券の「利子1%」と「利回り5.3%」は別もの

第2週で、さくらコーヒーの債券（100万円・年1%・10年）を思い出してください。あの債券が、**いま95万円で売られていた**とします。

- 95万円で買って、1年後に100万円が返ってくる（満期が近い場合をイメージ）
- もうけは **100 − 95 = 5万円**
- 払ったお金95万円に対するもうけの割合は 5 ÷ 95 ≈ **5.3%**

この「**1年で何%もうかったか**」が **利回り**です。債券に書いてある「利子1%」はあくまで額面に対する約束で、**実際にもうかる割合（利回り）は買った値段で変わる**——ここが初心者の落とし穴です。

言葉で言えば「もうけ ÷ 元手」の割合。貯金の金利と同じ感覚でOKです（複雑な利回りの定義はフェーズ2以降で）。

??? example "大人の式（クリックで表示。開かなくてOK）"
    \[
    \text{利回り} \approx \frac{\text{受け取るお金} - \text{払ったお金}}{\text{払ったお金}}
    \]
    - 分子 …もうけ（受け取るお金 − 払ったお金）
    - 分母 …元手（払ったお金）
    - 分数全体で「元手に対して何%もうかったか」

### 3-2 「債券の値段が下がる＝利回りが上がる」

2-5で見たシーソーを、利回りの言葉で言い直すとこうなります。

- 債券の**値段が下がって**買える → 同じ100万円を受け取れるのに**元手が少なくて済む** → **利回りは上がる**
- 債券の**値段が上がって**しまう → 元手が大きくなる → **利回りは下がる**

つまり「世の中の金利が上がる → 債券の値段が下がる → **結果的に利回りが新金利に追いつく**」。市場はこの「どこまで下がれば利回りが釣り合うか」を日々値段で調整しています。

### 3-3 ここで第1週の話がつながる

利回りを決める入力は「払った値段」「受け取る金額」「期間」……と**複数**あります。つまり利回りも多変数の関数で、第1週でやった「どの変数を動かすか」の考え方がそのまま使えます。

- 「**金利が1%動いたら、債券の値段は何%動くか**」→ これは第4週の **デュレーション** で学ぶ数字
- 「**株価が1円動いたら、オプションの値段はいくら動くか**」→ フェーズ2の **デルタ**

どちらも「**1つの変数だけ動かして感度を測る**」＝偏微分の使いどころです。「何かを測るときは、どれを動かすか決める」——この習慣が、この先のすべての単位で効いてきます。

### 3-4 Pythonで確かめる：利回りの計算

```python
def rimaawari(haratta, morau):      # 利回り = (受け取るお金 - 払ったお金) ÷ 払ったお金
    return (morau - haratta) / haratta

for price in [90, 95, 100]:
    print(f"債券を{price}万円で買う → 利回り ≈ {rimaawari(price, 100) * 100:.1f}%")
```

```text
債券を90万円で買う → 利回り ≈ 11.1%
債券を95万円で買う → 利回り ≈ 5.3%
債券を100万円で買う → 利回り ≈ 0.0%
```

買う値段が安いほど利回りが高い——シーソーの実感がつかめます。

| 多変数の関数 | 入力が2つ以上。**1つだけ動かして**考える | 偏微分 → デルタ・デュレーション（第4週・フェーズ2） |
| 時間の価値 | 同じ金額でも、**もらうのが早いほど価値が高い** | 債券の値段・金利の世界全部 |
| 現在価値と割引 | 将来のお金を (1+r)^t で割って「いまの価値」に直す | 債券価格・フェーズ2のデリバティブ価格 |
| 利回り | もうけ ÷ 元手。値段が下がれば利回りは上がる | リスク管理・投資判断 |

**今日の1行メモ**：「今日の100円は、明日の100円より高い。その差を決めるのが金利。」
